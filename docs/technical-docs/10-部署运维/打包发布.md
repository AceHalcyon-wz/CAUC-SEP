## 概述

CAUC-SEP 项目采用 **Nuitka + Electron + electron-builder** 组合作为主要打包发布方案，提供专业级的跨平台桌面应用。

### 打包方案架构

### 打包方案对比

| 打包方案 | 适用场景 | 优势 | 劣势 |
|----------|----------|------|------|
| **Nuitka + Electron + electron-builder** | 生产环境发布 | 原生编译、跨平台、自动更新、专业安装包 | 编译时间长、架构复杂 |
| PyInstaller | 快速测试 | 打包速度快、配置简单 | 启动慢、代码易反编译 |
| Docker | 服务器部署 | 环境隔离、易于扩展 | 需要 Docker 环境 |

### 环境要求

| 组件 | 版本要求 | 说明 |
|------|----------|------|
| Python | 3.13+ | 后端运行环境 |
| Node.js | 20 LTS | Electron 运行环境 |
| Visual Studio | 2022+ | MSVC 编译工具链（必需） |
| Windows SDK | 10.0.22621+ | Windows 开发套件 |
| Nuitka | 2.x | Python 编译器 |
| Electron | 30.x | 桌面应用框架 |
| electron-builder | 24.x | 安装包构建工具 |

## Nuitka 编译配置

Nuitka 是将 Python 代码编译为原生可执行文件的工具，相比 PyInstaller 具有更好的性能和代码保护。

### MSVC 编译工具链配置

**重要说明：本项目必须使用 Visual Studio 已安装的 MSVC 编译工具链，禁止使用 MinGW。**

Python 3.13 及以上版本不再支持 MinGW 编译器。

#### Visual Studio 安装要求

安装 Visual Studio 2022 时，必须包含以下组件：

```
Visual Studio 2022 Community
├── 工作负载
│   ├── ☑ 使用 C++ 的桌面开发
│   └── ☑ Python 开发（可选）
│
└── 单个组件
    ├── ☑ MSVC v143 - VS 2022 C++ x64/x86 生成工具
    ├── ☑ Windows 10 SDK 或 Windows 11 SDK
    └── ☑ C++ CMake tools for Windows
```

#### 验证 MSVC 环境

```batch
:: 检查 Visual Studio 安装
"C:\Program Files\Microsoft Visual Studio\Installer\vswhere.exe" -latest -property displayName

:: 检查 MSVC 编译器
where cl.exe

:: 预期输出示例
C:\Program Files\Microsoft Visual Studio\2022\Community\VC\Tools\MSVC\14.38.33130\bin\Hostx64\x64\cl.exe
```

### 核心编译参数

| 参数 | 说明 | 推荐值 |
|------|------|--------|
| `--standalone` | 独立部署模式，包含所有依赖 | **必选** |
| `--msvc` | MSVC 编译器版本 | `latest` |
| `--windows-console-mode` | 控制台模式 | `disable`（由 Electron 管理） |
| `--windows-icon-from-ico` | 应用图标 | `assets/icons/icon.ico` |
| `--include-data-files` | 嵌入数据文件 | 配置文件、资源 |
| `--include-package` | 包含Python包 | `pymodbus,fastapi,uvicorn` |
| `--enable-plugin` | 启用插件 | `anti-bloat`（减小体积） |
| `--jobs` | 并行编译进程数 | 4（24GB内存） |
| `--lto` | 链接时优化 | `yes` |

### 内存优化配置（24GB DDR5）

```
总内存: 24GB
├── 系统保留: 8GB
├── Nuitka编译: 8GB (4进程 × 2GB)
└── 可用内存: 8GB
```

| 内存大小 | --jobs 推荐值 |
|----------|---------------|
| 8GB | 1 |
| 16GB | 2 |
| 24GB | 4 |
| 32GB+ | 6-8 |

### Nuitka 编译脚本

```python
"""
CAUC-SEP Nuitka Build Script - Electron Integration
Python 3.13 + MSVC Compatible

功能:
1. 使用 MSVC 编译器（自动检测 Visual Studio）
2. 使用 standalone 模式
3. 输出到 electron/resources/backend/ 目录
4. 不嵌入前端静态文件（由 Electron 管理）
"""

import subprocess
import sys
import os
import shutil
from pathlib import Path
from datetime import datetime

PROJECT_ROOT = Path(__file__).parent.parent.parent
BACKEND_DIR = PROJECT_ROOT / "backend"
ICON_PATH = PROJECT_ROOT / "assets" / "icons" / "icon.ico"
ELECTRON_BACKEND_DIR = PROJECT_ROOT / "electron" / "resources" / "backend"

APP_NAME = "backend"
APP_VERSION = "3.5.0"
COMPANY_NAME = "CAUC"
DESCRIPTION = "CAUC Spintronics Experiment Platform"

NUITKA_ARGS = [
    sys.executable, "-m", "nuitka",
    "--standalone",
    "--windows-console-mode=disable",
    f"--windows-icon-from-ico={ICON_PATH}",
    f"--output-dir={ELECTRON_BACKEND_DIR.parent}",
    f"--output-filename={APP_NAME}.exe",
    f"--company-name={COMPANY_NAME}",
    f"--product-name=CAUC-SEP",
    f"--file-version={APP_VERSION}.0",
    f"--product-version={APP_VERSION}.0",
    f"--file-description={DESCRIPTION}",

    # MSVC 编译器配置（自动检测）
    "--msvc=latest",

    # 包含必要的包
    "--include-package=fastapi",
    "--include-package=uvicorn",
    "--include-package=pydantic",
    "--include-package=pydantic_settings",
    "--include-package=sqlalchemy",
    "--include-package=numpy",
    "--include-package=core",
    "--include-package=api",
    "--include-package=middleware",
    "--include-package=models",
    "--include-package=drivers",

    # 排除不需要的模块
    "--nofollow-import-to=tkinter",
    "--nofollow-import-to=unittest",
    "--nofollow-import-to=pytest",
    "--nofollow-import-to=PIL",
    "--nofollow-import-to=cv2",
    "--nofollow-import-to=pandas",
    "--nofollow-import-to=matplotlib",
    "--nofollow-import-to=scipy",

    # 性能优化
    "--assume-yes-for-downloads",
    "--show-progress",
    "--show-memory",
    "--jobs=4",
    "--lto=yes",

    "main.py"
]


def main():
    print("=" * 60)
    print(f"CAUC-SEP Build Script (Electron Integration)")
    print(f"Python: {sys.version}")
    print(f"编译器: MSVC (自动检测)")
    print(f"输出目录: {ELECTRON_BACKEND_DIR}")
    print("=" * 60)

    os.chdir(BACKEND_DIR)
    result = subprocess.run(NUITKA_ARGS)

    if result.returncode == 0:
        print("\n编译成功!")
        print(f"输出目录: {ELECTRON_BACKEND_DIR}")
    else:
        print(f"\n编译失败, 返回码: {result.returncode}")

    return result.returncode


if __name__ == "__main__":
    sys.exit(main())
```

## 构建脚本

### 完整构建脚本 (build-all.bat)

```batch
@echo off
chcp 65001 >nul
REM ============================================================================
REM CAUC-SEP 完整构建脚本 v3.5
REM
REM 功能: 前端构建 + Nuitka编译 + Electron打包
REM 更新: 2026-03-15
REM ============================================================================

setlocal EnableDelayedExpansion

echo.
echo ==========================================
echo   CAUC-SEP 完整构建流程 v3.5
echo   Nuitka + Electron + electron-builder
echo ==========================================
echo.

cd /d "%~dp0\.."

set "APP_VERSION=3.5.0"
set "PROJECT_ROOT=%cd%"

REM ============================================================================
REM 1. 构建前端
REM ============================================================================

echo [1/3] 构建前端...

cd frontend
if not exist "node_modules" (
    echo   - 安装前端依赖...
    call npm install --silent
)

echo   - 执行Vite构建...
call npm run build
if errorlevel 1 (
    echo [错误] 前端构建失败
    cd ..
    pause
    exit /b 1
)

REM 复制前端构建产物到 Electron 资源目录
echo   - 复制前端资源到 Electron...
if not exist "..\electron\resources\frontend" mkdir "..\electron\resources\frontend"
xcopy /E /Y "dist\*" "..\electron\resources\frontend\"

cd ..
echo   - 前端构建完成

REM ============================================================================
REM 2. Nuitka编译后端 (MSVC)
REM ============================================================================

echo.
echo [2/3] Nuitka编译后端 (MSVC)...
echo   - 这可能需要10-30分钟，请耐心等待
echo.

cd backend
python scripts\build_exe_standalone.py
if errorlevel 1 (
    echo [错误] Nuitka编译失败
    cd ..
    pause
    exit /b 1
)
cd ..
echo   - 后端编译完成

REM ============================================================================
REM 3. Electron打包
REM ============================================================================

echo.
echo [3/3] Electron打包...

cd electron
if not exist "node_modules" (
    echo   - 安装Electron依赖...
    call npm install --silent
)

echo   - 执行electron-builder...
call npm run build:win
if errorlevel 1 (
    echo [警告] Electron打包失败，请检查配置
) else (
    echo   - Electron打包完成
)
cd ..

REM ============================================================================
REM 完成
REM ============================================================================

echo.
echo ==========================================
echo   构建成功！
echo ==========================================
echo.

echo 输出文件:
if exist "electron\dist\CAUC-SEP-3.5.0-x64-setup.exe" (
    echo   - 安装包: electron\dist\CAUC-SEP-3.5.0-x64-setup.exe
)

echo.
echo 按任意键退出...
pause >nul
```

echo MSVC 编译器版本:
cl 2>&1 | findstr "版本"

   ```bash
   # 更新 package.json 版本号
   # 更新 electron/package.json 版本号
   # 更新 CHANGELOG.md
   ```

2. **执行构建**
   ```bash
   # Windows
   scripts\build-all.bat
   
   # 或分步执行
   cd frontend && npm run build && cd ..
   cd backend && python scripts/build_exe_standalone.py && cd ..
   cd electron && npm run build:win && cd ..
   ```

   - 在干净的 Windows 10/11 系统上测试安装
   - 验证所有功能正常
   - 检查卸载是否干净

4. **发布到 GitHub Releases**
   ```bash
   # 创建 Git 标签

   # 上传安装包到 GitHub Releases
   # 或配置 electron-builder 自动发布
   ```

## 常见问题与解决方案

### Q1: Nuitka 编译时间太长？

**原因**: Nuitka 首次编译需要编译所有依赖

**解决方案**:
1. 首次编译 10-30 分钟是正常的
2. 后续增量编译会快很多
3. 使用 `--jobs=4` 增加并行度
4. 不要删除 `.build` 目录（缓存）

### Q2: 内存不足错误？

**原因**: 并行编译进程占用内存过多

**解决方案**:
| 内存大小 | --jobs 值 |
|----------|-----------|
| 8GB | 1 |
| 16GB | 2 |
| 24GB | 4 |

### Q3: 杀毒软件误报？

**原因**: 编译的 EXE 缺少数字签名

**解决方案**:
1. 申请代码签名证书（推荐）
2. 将 EXE 添加到杀毒软件白名单
3. 提交样本到杀毒软件厂商

### Q4: Electron 启动后端失败？

**原因**: 后端可执行文件路径错误或依赖缺失

**解决方案**:
1. 检查 `electron/resources/backend/main.dist/` 目录是否存在
2. 确认 `backend.exe` 及所有依赖文件完整
3. 手动运行后端 EXE 检查错误信息
4. 检查端口 8000 是否被占用

### Q5: 前端无法连接后端 API？

**原因**: 后端服务未启动或 CORS 配置问题

**解决方案**:
1. 确认后端服务已成功启动
2. 检查 CORS 配置是否正确
3. 确认 API 请求地址为 `http://127.0.0.1:8000`
4. 开发环境检查 Vite 代理配置

### Q6: 安装包体积过大？

**原因**: Electron 运行时约 60-80MB 是正常的

**解决方案**:
1. Electron 运行时约 60-80MB 是正常的
2. 使用 `asar` 压缩前端资源
3. 启用 `--enable-plugin=anti-bloat` 减小后端体积
4. 考虑使用增量更新减少下载量

### Q7: MSVC 编译器未检测到？

**原因**: Visual Studio 未正确安装或环境变量问题

**解决方案**:
1. 确认安装了 Visual Studio 2022
2. 确保勾选"使用 C++ 的桌面开发"工作负载
3. 运行 `vswhere.exe` 检查安装状态
4. 重启终端或系统后重试

### Q8: Python 3.13 编译报错？

**原因**: 使用了不兼容的编译器参数

**解决方案**:
1. 确保使用 `--msvc=latest` 参数
2. 移除 `--zig` 和 `--mingw64` 参数
3. 更新 Nuitka 到最新版本：`pip install -U nuitka`

### Q9: 安装后应用白屏？

**原因**: 前端资源加载失败或缺少错误监听

**诊断步骤**:
1. 按 F12 打开开发者工具查看控制台错误
2. 检查日志文件：`%APPDATA%\cauc-sep\logs\main.log`
3. 验证前端资源路径：`resources\frontend\index.html`

**解决方案**:
1. 确保前端构建产物完整复制到 `electron\resources\frontend\`
2. 检查 `vite.config.ts` 中 `base: './'` 配置正确
3. 确认 `main.js` 中添加了 `did-fail-load` 事件监听
4. 验证 `webSecurity: true` 不阻止本地文件加载

**调试技巧**:
```javascript
// main.js 中添加错误监听
this.window?.webContents.on("did-fail-load", (event, errorCode, errorDescription) => {
  log.error(`[Frontend] 页面加载失败: ${errorCode} - ${errorDescription}`);
});

// 生产环境按 F12 可打开开发者工具
this.window?.webContents.on("before-input-event", (event, input) => {
  if (input.key === "F12") {
    this.window?.webContents.toggleDevTools();
  }
});
```

### Q10: 前端资源路径错误？

**原因**: Vite 构建时 `base` 配置不正确

**解决方案**:
```typescript
// vite.config.ts
export default defineConfig({
  base: './',  // 使用相对路径，确保 Electron 加载本地文件正确
  build: {
    outDir: 'dist',
    assetsDir: 'assets',
  }
})
```
