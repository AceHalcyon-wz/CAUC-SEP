## 一、版本号规范

### 1.1 语义化版本 (Semantic Versioning)

CAUC-SEP 项目采用语义化版本号规范，格式为：`MAJOR.MINOR.PATCH`

```
版本号格式: X.Y.Z[-PRERELEASE][+BUILD]

示例:
  4.0.0           # 正式版本
  4.1.0-alpha.1   # Alpha 预发布版本
  4.1.0-beta.2    # Beta 预发布版本
  4.1.0-rc.1      # Release Candidate
  4.0.0+20260325  # 带构建元数据
```

### 1.2 版本号递增规则

| 版本类型 | 递增条件 | 示例 |
|---------|---------|------|
| **MAJOR** | 不兼容的 API 变更 | 3.x.x → 4.0.0 |
| **MINOR** | 向后兼容的功能新增 | 4.0.x → 4.1.0 |
| **PATCH** | 向后兼容的问题修复 | 4.0.0 → 4.0.1 |

### 1.3 预发布版本

| 类型 | 说明 | 稳定性 |
|------|------|--------|
| `alpha` | 内部测试版本，功能不完整 | 不稳定 |
| `beta` | 公开测试版本，功能基本完整 | 较稳定 |
| `rc` | 发布候选版本，准备正式发布 | 稳定 |

### 1.4 版本号同步

项目使用统一的版本号，需要在以下文件中保持一致：

```
项目根目录/
├── backend/
│   └── pyproject.toml          # 主版本号定义
├── frontend/
│   └── package.json            # 前端版本号
├── electron/
│   └── package.json            # Electron版本号
├── CHANGELOG.md                # 更新日志
└── VERSION                     # 版本文件
```

**同步方法**：

```bash
# 使用版本同步脚本
python backend/scripts/sync_version.py [version]

# 示例：设置新版本
python backend/scripts/sync_version.py 4.1.0
```

## 二、Git 分支管理策略

### 2.1 分支模型

```
main (生产分支)
  │
  ├── develop (开发分支)
  │     │
  │     ├── feature/xxx (功能分支)
  │     ├── feature/yyy
  │     │
  │     └── release/x.y.z (发布分支)
  │           │
  │           └── main (合并后打标签)
  │
  └── hotfix/xxx (紧急修复分支)
        │
        └── main (合并后打标签)
```

### 2.2 分支类型说明

| 分支类型 | 命名规范 | 生命周期 | 说明 |
|---------|---------|---------|------|
| `main` | `main` | 永久 | 生产环境代码，只接受合并 |
| `develop` | `develop` | 永久 | 开发主分支，功能集成 |
| `feature` | `feature/功能名` | 临时 | 新功能开发 |
| `release` | `release/x.y.z` | 临时 | 发布准备 |
| `hotfix` | `hotfix/问题描述` | 临时 | 紧急修复 |

### 2.3 分支操作规范

#### 创建功能分支

```bash
# 从 develop 创建功能分支
git checkout develop
git pull origin develop
git checkout -b feature/motor-control-enhancement

# 开发完成后合并回 develop
git checkout develop
git merge --no-ff feature/motor-control-enhancement
git push origin develop
git branch -d feature/motor-control-enhancement
```

#### 创建发布分支

```bash
# 从 develop 创建发布分支
git checkout develop
git checkout -b release/4.1.0

# 更新版本号
python backend/scripts/sync_version.py 4.1.0

# 更新 CHANGELOG
# 修复 bug、完善文档

# 合并到 main
git checkout main
git merge --no-ff release/4.1.0
git tag -a v4.1.0 -m "Release v4.1.0"
git push origin main --tags

# 合并回 develop
git checkout develop
git merge --no-ff release/4.1.0
git push origin develop
git branch -d release/4.1.0
```

#### 创建热修复分支

```bash
# 从 main 创建热修复分支
git checkout main
git checkout -b hotfix/critical-bug-fix

# 修复问题
# 更新版本号（PATCH）
python backend/scripts/sync_version.py 4.0.1

# 合并到 main
git checkout main
git merge --no-ff hotfix/critical-bug-fix
git tag -a v4.0.1 -m "Hotfix v4.0.1"
git push origin main --tags

# 合并到 develop
git checkout develop
git merge --no-ff hotfix/critical-bug-fix
git push origin develop
git branch -d hotfix/critical-bug-fix
```

## 三、Commit 规范

### 3.1 Commit 消息格式

```
<type>(<scope>): <subject>

<body>

<footer>
```

### 3.2 Type 类型

| Type | 说明 | 示例 |
|------|------|------|
| `feat` | 新功能 | `feat(motor): 添加PR路径编程功能` |
| `fix` | Bug修复 | `fix(api): 修复WebSocket连接断开问题` |
| `docs` | 文档更新 | `docs(readme): 更新安装说明` |
| `style` | 代码格式 | `style: 格式化代码` |
| `refactor` | 重构 | `refactor(motor): 重构驱动层代码` |
| `perf` | 性能优化 | `perf(websocket): 优化消息推送性能` |
| `test` | 测试 | `test(api): 添加电机控制API测试` |
| `chore` | 构建/工具 | `chore(ci): 更新GitHub Actions配置` |
| `revert` | 回滚 | `revert: 回滚某次提交` |

### 3.3 Scope 范围

```
backend/   - 后端相关
  api      - API接口
  core     - 核心模块
  driver   - 设备驱动
  db       - 数据库
  test     - 测试

frontend/  - 前端相关
  component - 组件
  store    - 状态管理
  api      - API调用
  view     - 页面

electron/  - Electron相关
ci/        - CI/CD相关
docs/      - 文档相关
```

### 3.4 Commit 示例

```bash
# 功能新增
git commit -m "feat(motor): 添加16段PR路径编程功能

- 支持PR路径配置保存
- 支持PR路径触发执行
- 添加路径参数校验

Closes #123"

# Bug修复
git commit -m "fix(websocket): 修复连接断开后自动重连失败问题

问题：WebSocket断开后无法自动重连
原因：重连逻辑中状态未正确重置
解决：添加状态重置逻辑

Fixes #456"
```

## 四、发布流程

### 4.1 发布前检查清单

```markdown
## 发布前检查清单

### 代码质量
- [ ] 所有测试通过
- [ ] 代码覆盖率 ≥ 80%
- [ ] 无 ESLint/Ruff 警告
- [ ] 无 TypeScript 类型错误

### 版本管理
- [ ] 版本号已更新
- [ ] CHANGELOG.md 已更新
- [ ] Git 标签已创建

### 文档
- [ ] API 文档已更新
- [ ] 用户手册已更新
- [ ] README.md 已更新

### 构建
- [ ] 前端构建成功
- [ ] 后端编译成功
- [ ] Electron 打包成功
- [ ] 安装包测试通过
```

### 4.2 发布步骤

```bash
# 1. 创建发布分支
git checkout develop
git checkout -b release/4.1.0

# 2. 更新版本号
python backend/scripts/sync_version.py 4.1.0

# 3. 更新 CHANGELOG
# 编辑 CHANGELOG.md

# 4. 运行测试
cd backend && pytest
cd ../frontend && npm run test:run

# 5. 构建产物
cd ..
scripts/build-all.bat

# 6. 合并到 main
git checkout main
git merge --no-ff release/4.1.0
git tag -a v4.1.0 -m "Release v4.1.0"
git push origin main --tags

# 7. 创建 GitHub Release
# 上传安装包到 GitHub Releases

# 8. 合并回 develop
git checkout develop
git merge --no-ff release/4.1.0
git push origin develop

# 9. 清理
git branch -d release/4.1.0
```

## 五、CHANGELOG 规范

### 5.1 格式

```markdown
# 更新日志

## [X.Y.Z] - YYYY-MM-DD

### 新增 (Added)
- 新功能描述

### 变更 (Changed)
- 变更描述

### 修复 (Fixed)
- Bug修复描述

### 移除 (Removed)
- 移除功能描述

### 安全 (Security)
- 安全相关更新
```

### 5.2 示例

```markdown
## [4.1.0] - 2026-04-01

### 新增
- **PR路径编程**: 支持16段PR路径配置与触发执行
- **数据分析**: 新增磁滞回线自动分析功能
- **用户管理**: 支持用户角色权限管理

### 变更
- **API优化**: 重构电机控制API，提升响应速度30%
- **UI改进**: 优化设备控制面板布局

### 修复
- **WebSocket**: 修复连接断开后自动重连失败问题 (#123)
- **温度控制**: 修复PID参数设置不生效问题

### 安全
- **认证**: 增强JWT令牌安全性
```

## 六、版本生命周期

### 6.1 支持策略

| 版本类型 | 支持周期 | 说明 |
|---------|---------|------|
| 最新版本 | 持续支持 | 持续修复Bug、安全漏洞 |
| 前一版本 | 6个月 | 仅修复严重Bug、安全漏洞 |
| 更早版本 | 不支持 | 建议升级到最新版本 |

### 6.2 版本废弃流程

1. **发布公告**: 提前3个月发布版本废弃公告
2. **停止维护**: 停止新功能开发
3. **安全修复**: 仅修复严重安全漏洞
4. **正式废弃**: 不再提供任何支持
