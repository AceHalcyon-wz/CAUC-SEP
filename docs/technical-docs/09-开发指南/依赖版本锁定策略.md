## 一、概述

CAUC-SEP 项目采用严格的依赖版本锁定策略，确保开发、测试、生产环境的一致性，避免因依赖版本变化导致的意外问题。

### 1.1 锁定策略原则

1. **精确版本锁定**: 所有依赖必须锁定到精确版本
2. **Lock文件提交**: 所有 lock 文件必须提交到版本控制
3. **定期更新**: 定期检查并更新依赖版本
4. **安全优先**: 及时修复安全漏洞
5. **最小变更**: 仅在必要时更新依赖

## 二、后端依赖管理 (Python)

### 2.1 依赖文件结构

```
backend/
├── requirements.txt        # 生产依赖（精确版本）
├── requirements.lock       # pip-compile 生成的锁定文件
├── requirements-test.txt   # 测试依赖
└── pyproject.toml         # 项目配置和开发依赖
```

### 2.2 版本约束规范

#### requirements.txt 格式

```text
# 格式: 包名==精确版本
# 说明: 必须使用 == 锁定精确版本

# ==================== Web框架 ====================
fastapi==0.109.2
uvicorn[standard]==0.27.1

# ==================== 硬件通信 ====================
pymodbus==3.5.4
pyserial==3.5

# ==================== 数据处理 ====================
numpy==1.26.4
scipy==1.12.0
```

#### 版本约束符号

| 符号 | 说明 | 使用场景 |
|-----|------|---------|
| `==` | 精确版本 | **生产依赖（推荐）** |
| `>=` | 最小版本 | 不推荐 |
| `~=` | 兼容版本 | 不推荐 |
| `>=,<` | 版本范围 | 不推荐 |

### 2.3 pip-tools 使用

#### 安装 pip-tools

```bash
pip install pip-tools
```

#### 创建 requirements.in

```text
# requirements.in - 声明直接依赖（不锁定版本）
fastapi>=0.109.0
uvicorn[standard]>=0.27.0
pymodbus>=3.5.0
```

#### 生成锁定文件

```bash
# 编译生成 requirements.txt
pip-compile requirements.in

# 输出示例
# fastapi==0.109.2
#     via -r requirements.in
# uvicorn==0.27.1
#     via -r requirements.in
```

#### 更新依赖

```bash
# 更新所有依赖
pip-compile --upgrade requirements.in

# 更新特定包
pip-compile --upgrade-package fastapi requirements.in
```

### 2.4 pyproject.toml 配置

```toml
[project]
name = "cauc-sep-backend"
version = "4.0.0"
requires-python = ">=3.13"

# 生产依赖（使用范围约束）
dependencies = [
    "fastapi>=0.109.0,<0.110.0",
    "uvicorn[standard]>=0.27.0,<0.28.0",
    "pymodbus>=3.5.0,<4.0.0",
]

# 开发依赖
[project.optional-dependencies]
dev = [
    "black==25.1.0",
    "isort==6.0.1",
    "ruff==0.11.2",
    "mypy==1.15.0",
    "pytest==8.3.5",
    "pytest-cov==6.0.0",
]
```

## 三、前端依赖管理 (Node.js)

### 3.1 依赖文件结构

```
frontend/
├── package.json           # 依赖声明
├── package-lock.json      # npm 锁定文件（必须提交）
└── node_modules/          # 依赖安装目录（不提交）
```

### 3.2 版本约束规范

#### package.json 格式

```json
{
  "dependencies": {
    "vue": "3.5.13",
    "element-plus": "2.13.5",
    "axios": "1.8.3"
  },
  "devDependencies": {
    "vite": "6.2.2",
    "typescript": "5.8.2",
    "vitest": "3.0.9"
  }
}
```

#### 版本约束符号

| 符号 | 说明 | 使用场景 |
|-----|------|---------|
| `精确版本` | `1.2.3` | **生产依赖（推荐）** |
| `^` | 兼容版本 | `^1.2.3` = `>=1.2.3 <2.0.0` |
| `~` | 补丁版本 | `~1.2.3` = `>=1.2.3 <1.3.0` |
| `>=` | 最小版本 | 不推荐 |

### 3.3 package-lock.json

**重要**: `package-lock.json` 必须提交到版本控制！

#### 作用

1. 锁定所有依赖的精确版本
2. 锁定依赖树结构
3. 确保团队成员安装相同版本
4. 确保 CI/CD 环境一致性

#### 安装命令

```bash
# 安装依赖（优先使用 lock 文件）
npm ci

# 不要使用 npm install（会更新 lock 文件）
# npm install
```

### 3.4 依赖更新流程

#### 检查过时依赖

```bash
npm outdated
```

#### 更新依赖

```bash
# 更新补丁版本（安全）
npm update

# 更新特定包
npm install vue@3.5.14 --save

# 更新到最新版本（谨慎）
npm install vue@latest --save
```

#### 安全审计

```bash
# 检查安全漏洞
npm audit

# 自动修复
npm audit fix

# 强制修复（可能有破坏性变更）
npm audit fix --force
```

## 五、CI/CD 环境依赖管理

### 5.1 GitHub Actions 配置

```yaml
# 后端依赖缓存
- name: 设置 Python 环境
  uses: actions/setup-python@v5
  with:
    python-version: '3.13'
    cache: 'pip'

- name: 安装依赖
  working-directory: backend
  run: |
    pip install --upgrade pip
    pip install -r requirements.txt
```

```yaml
# 前端依赖缓存
- name: 设置 Node.js 环境
  uses: actions/setup-node@v4
  with:
    node-version: '20'
    cache: 'npm'
    cache-dependency-path: frontend/package-lock.json

- name: 安装依赖
  working-directory: frontend
  run: npm ci
```

### 5.2 依赖安装最佳实践

| 环境 | 命令 | 说明 |
|-----|------|------|
| 开发环境 | `npm install` | 允许更新 lock 文件 |
| CI/CD | `npm ci` | 严格按照 lock 文件安装 |
| 生产部署 | `npm ci --production` | 仅安装生产依赖 |

## 六、依赖更新策略

### 6.1 定期更新计划

| 类型 | 频率 | 操作 |
|-----|------|------|
| 安全补丁 | 立即 | `npm audit fix` |
| 补丁版本 | 每周 | `npm update` |
| 次版本 | 每月 | 评估后更新 |
| 主版本 | 按需 | 充分测试后更新 |

### 6.2 更新检查清单

```markdown
## 依赖更新检查清单

### 更新前
- [ ] 检查 CHANGELOG 了解变更内容
- [ ] 检查是否有破坏性变更
- [ ] 创建新的功能分支

### 更新中
- [ ] 更新单个依赖
- [ ] 运行测试
- [ ] 检查类型错误
- [ ] 手动测试关键功能

### 更新后
- [ ] 提交 lock 文件
- [ ] 更新 CHANGELOG
- [ ] 创建 Pull Request
```

### 6.3 安全漏洞处理

```bash
# 1. 检查漏洞
npm audit

# 2. 查看漏洞详情
npm audit --json

# 3. 自动修复
npm audit fix

# 4. 如果无法自动修复，手动更新
npm install package-name@fixed-version

# 5. 如果暂时无法修复，使用 overrides
# package.json
{
  "overrides": {
    "vulnerable-package": "fixed-version"
  }
}
```

## 八、常见问题

### Q1: 为什么使用精确版本锁定？

**答**: 精确版本锁定确保所有环境安装相同版本，避免因版本差异导致的问题。

### Q2: package-lock.json 冲突怎么办？

**答**: 
```bash
# 删除 node_modules 和 lock 文件
rm -rf node_modules package-lock.json

# 重新安装
npm install

# 解决冲突后提交新的 lock 文件
```

### Q3: 如何处理依赖安全漏洞？

**答**:
1. 优先使用 `npm audit fix` 自动修复
2. 无法自动修复时，手动更新到安全版本
3. 如果依赖未发布修复版本，考虑使用替代方案

### Q4: CI/CD 中应该使用 npm install 还是 npm ci？

**答**: 必须使用 `npm ci`，它严格按照 lock 文件安装，速度更快，且不会修改 lock 文件。
