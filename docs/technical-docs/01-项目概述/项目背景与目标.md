## 1. 项目背景

### 1.1 项目起源

**CAUC-SEP** (CAUC Spintronic Experiment Platform) 是一套完整的自旋电子器件/材料特性采集与分析实验平台，专为材料物理专业的实验研究而设计。

项目发起人是一名大二材料物理专业学生，导师最初要求使用 LabVIEW 开发该实验平台。经过技术调研，决定采用 Python 技术栈实现，并参考 VCP (Virtual Control Platform) 项目的前后分离架构设计理念。该方案具有以下优势：

| 对比维度 | LabVIEW | Python 技术栈 |
|---------|---------|--------------|
| 开发效率 | 较低，图形化编程调试困难 | 高，代码可读性强 |
| 可维护性 | 差，版本控制困难 | 强，Git 友好 |
| 社区支持 | 有限，商业软件 | 丰富，开源生态 |
| 扩展性 | 受限于 NI 生态 | 灵活，可集成多种库 |
| 成本 | 高昂（商业授权） | 低（开源免费） |

### 1.2 应用场景

本平台主要服务于以下实验场景：

1. **自旋电子器件特性测量**：测量自旋阀、磁性隧道结等器件的磁阻特性
2. **材料磁性分析**：分析薄膜材料的磁滞回线、矫顽力、剩磁等参数
3. **温度依赖性研究**：研究材料特性随温度变化的规律
4. **精密位移控制**：纳米级精度的样品定位和扫描

### 1.3 硬件集成需求

平台需要集成多种实验设备：

- **雷赛 DM2C-RS556 驱控一体型步进驱动器**：通过 RS-485 接口基于 Modbus RTU 协议进行通信
- **电磁铁控制系统**：提供可变磁场环境
- **温控系统**：实现液氮釜温度的精确控制
- **压电陶瓷控制器**：实现纳米级精密位移
- **微电流采集系统**：实现 pA级微弱电流信号采集

## 2. 设计目标

### 2.1 功能目标

#### 2.1.1 运动控制系统

| 功能模块 | 具体功能 | 技术指标 |
|---------|---------|---------|
| 步进电机控制 | PR模式精确定位 | 支持16段位置表编程 |
| 位置控制 | 绝对/相对定位 | 位置精度可达微米级 |
| JOG模式 | 点动控制 | 可配置速度和加速度 |
| 回零操作 | 多种回零模式 | 支持10种回零模式 |
| 安全保护 | 软件限位 | 防止机械撞机 |

#### 2.1.2 电磁铁控制

| 功能模块 | 具体功能 | 技术指标 |
|---------|---------|---------|
| 恒流模式 | 精确设定目标电流 | 电流分辨率：mA级 |
| 扫描模式 | 正向/反向/三角波扫描 | 可配置步长和停留时间 |
| 校准管理 | 电流-磁场校准曲线 | 支持校准数据持久化 |

#### 2.1.3 温度控制系统

| 功能模块 | 具体功能 | 技术指标 |
|---------|---------|---------|
| PID控制 | PID参数配置 | 支持自动调谐 |
| 程序控温 | 多段温度程序编排 | 可配置升降温速率 |
| 保护功能 | 温度限值保护 | 超温自动保护 |

#### 2.1.4 压电控制

| 功能模块 | 具体功能 | 技术指标 |
|---------|---------|---------|
| 控制模式 | 电压/位移控制 | 纳米级分辨率 |
| 工作模式 | 开环/闭环切换 | 支持多种校准方式 |

#### 2.1.5 数据采集与分析

| 功能模块 | 具体功能 | 技术指标 |
|---------|---------|---------|
| 微电流采集 | 多通道同步采集 | pA级灵敏度 |
| 信号处理 | 数字滤波、背景扣除 | Savitzky-Golay 滤波 |
| 曲线拟合 | Langevin函数拟合 | 支持多种拟合模型 |
| 磁滞分析 | 矫顽力、剩磁计算 | 自动参数提取 |

#### 2.1.6 实验管理

- 可视化实验流程编排
- 实时数据看板
- 多格式数据导出（CSV/HDF5）

### 2.2 技术目标

#### 2.2.1 架构目标

| 目标 | 具体要求 | 实现方案 |
|-----|---------|---------|
| 前后端分离 | 独立开发、独立部署 | Vue3 + FastAPI |
| 实时通信 | 低延迟数据推送 | WebSocket |
| 跨平台 | Windows 10/11 64位 | Electron / PyInstaller |
| 单文件部署 | 打包为单一可执行文件 | .exe 格式 |

#### 2.2.2 性能目标

| 指标 | 目标值 | 说明 |
|-----|-------|------|
| 关键控制回路响应时间 | < 10ms | 运动控制指令响应 |
| WebSocket 推送延迟 | < 50ms | 实时数据更新 |
| 安装包体积 | < 200MB | 单一可执行文件 |
| 启动时间 | < 5s | 应用冷启动 |

#### 2.2.3 可靠性目标

| 指标 | 目标值 | 说明 |
|-----|-------|------|
| 系统可用性 | > 99.5% | 不含硬件故障 |
| 数据完整性 | 100% | 实验数据不丢失 |
| 错误恢复 | 自动恢复 | 支持断线重连 |

## 3. 核心特性

### 3.1 多设备统一管理

平台实现了多种实验设备的统一接入和管理：

```
┌─────────────────────────────────────────────────────────┐
│                    统一设备管理器                         │
├─────────────────────────────────────────────────────────┤
│  ┌─────────┐  ┌─────────┐  ┌─────────┐  ┌─────────┐   │
│  │步进电机  │  │ 电磁铁  │  │温控器   │  │压电控制 │   │
│  │ DM2C    │  │        │  │        │  │        │   │
│  └─────────┘  └─────────┘  └─────────┘  └─────────┘   │
│  ┌─────────┐                                            │
│  │皮安表   │                                            │
│  └─────────┘                                            │
└─────────────────────────────────────────────────────────┘
```

### 3.2 实时数据推送

基于 WebSocket 的实时数据流：

- **推送频率控制**：可配置数据推送频率
- **消息压缩**：支持 MessagePack 二进制序列化
- **背压处理**：防止数据积压导致的内存溢出
- **断线重连**：自动检测连接状态并重连

### 3.3 高级运动控制

针对 DM2C 步进驱动器的深度集成：

- **16段PR路径编程**：支持复杂运动轨迹
- **软件限位保护**：防止机械撞机
- **多种回零模式**：适应不同应用场景
- **IO端口配置**：灵活的数字IO功能映射

### 3.4 数据分析引擎

内置专业的物理数据分析功能：

| 分析类型 | 算法/方法 | 应用场景 |
|---------|----------|---------|
| 信号平滑 | Savitzky-Golay 滤波 | 噪声抑制 |
| 曲线拟合 | Langevin 函数拟合 | 超顺磁特性分析 |
| 磁滞分析 | 参数提取算法 | 磁性材料表征 |

### 3.5 安全机制

多层次的安全保障：

| 安全层级 | 机制 | 说明 |
|---------|-----|------|
| 网络安全 | 速率限制 | 防止 API 滥用 |
| 数据安全 | 审计日志 | 操作可追溯 |
| 通信安全 | 安全响应头 | 防止常见攻击 |
| 设备安全 | 过流保护 | 硬件保护机制 |

## 4. 架构决策说明

### 4.1 为什么选择 Python 技术栈？

| 决策因素 | 分析 |
|---------|------|
| **科学计算生态** | NumPy、SciPy、lmfit 等库提供完整的科学计算支持 |
| **硬件通信** | PyModbus、PySerial 成熟稳定，支持多种通信协议 |
| **Web开发** | FastAPI 高性能异步框架，自动生成 API 文档 |
| **可维护性** | 代码可读性强，便于后续维护和扩展 |
| **成本** | 开源免费，无商业授权费用 |

### 4.2 为什么选择前后端分离架构？

| 决策因素 | 分析 |
|---------|------|
| **开发效率** | 前后端可并行开发，提高效率 |
| **可扩展性** | 前端可独立升级，不影响后端 |
| **用户体验** | 现代化 UI 框架，响应式设计 |
| **部署灵活** | 可独立部署，支持分布式架构 |

### 4.3 为什么选择 FastAPI？

| 决策因素 | 分析 |
|---------|------|
| **性能** | 基于 Starlette 和 Pydantic，性能优异 |
| **异步支持** | 原生支持 async/await，适合 I/O 密集型应用 |
| **类型提示** | 自动数据验证和序列化 |
| **文档生成** | 自动生成 Swagger/OpenAPI 文档 |
| **WebSocket** | 原生支持 WebSocket 实时通信 |

### 4.4 为什么选择 Vue 3？

| 决策因素 | 分析 |
|---------|------|
| **Composition API** | 更好的代码组织和复用 |
| **性能** | 更快的渲染速度和更小的包体积 |
| **TypeScript 支持** | 更好的类型推导 |
| **生态系统** | Element Plus、ECharts 等成熟组件库 |
